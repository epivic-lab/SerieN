# Registro adapter — contratti futuri, nessun adapter implementato in U0

Gli adapter non possiedono stato ferroviario. Input da getter reali, output per proiezioni UI o chiamate singole ai dispatcher esistenti; stato successivo sempre riletto. Ogni microfase richiede cleanup degli handler e verifica di assenza di azioni duplicate.

Ignorare doppi click, azzerare token su cancel/close/dispose. Non invocare `.onclick`, non duplicare signOut/reload e non cambiare Auth. Verificare che gli handler generici modali non riaprano la guard | Spy al confine del listener esistente: 0 chiamate prima/cancel, esattamente 1 dopo consenso anche con input ripetuti; cancellazione conserva stato |
